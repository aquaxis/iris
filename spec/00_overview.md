## 0.1 IRIS言語とは

**IRIS** (アイリス: Immutable RTL Implementation Standard) は、SystemVerilogの複雑さを解消し、Rustの設計思想を取り入れたハードウェア記述言語です。

### 0.1.1 背景

SystemVerilogは強力なハードウェア記述言語ですが、以下の問題を抱えています：

- 歴史的経緯による複雑な構文（約220の予約語）
- 暗黙の型変換によるバグの温床
- `begin...end`などの冗長な記法
- `reg`, `wire`, `logic`の使い分けの混乱
- 意図しないラッチ生成のリスク
- ブロッキング代入（`=`）とノンブロッキング代入（`<=`）の混乱

### 0.1.2 参考言語・仕様

IRISは以下の言語・仕様を参考にしています：

- **SystemVerilog**: 構文
- **Rust**: 所有権モデル、型安全性、明示的な構文

## 0.2 設計思想

### 0.2.1 原則

| 原則 | 説明 |
|------|------|
| **Safety First** | 暗黙の型変換を廃止、ビット幅不一致はコンパイルエラー |
| **明示性 > 暗黙性** | 意図を明確にコードで表現 |
| **簡潔性** | `{}`記法、統一されたデータ型、統一された代入演算子 |
| **構成可能性** | モジュール間の疎結合設計 |
| **合成と検証の分離** | 合成可能/検証専用コードの明確な区別 |

### 0.2.2 設計目標

| 目標 | SystemVerilogの問題 | IRISの解決策 |
|------|---------------------|--------------|
| 明確性 | 同じ機能に複数構文 | 一機能一構文 |
| 型安全性 | 暗黙の型変換 | 明示的型付け + 型推論 |
| 学習容易性 | 歴史的経緯による複雑さ | Rust風のクリーンな設計 |
| 合成可能性 | 境界が曖昧 | 明確なサブセット分離 |
| 検証統合 | UVMへの依存 | 言語組み込み検証機能 |

## 0.3 主要な特徴

### 0.3.1 代入演算子の統一

IRISでは、ブロッキング代入（`=`）とノンブロッキング代入（`<=`）の概念を廃止し、代入演算子を `=` に統一しています。

```rust
// IRIS: 統一された代入演算子
sync(clk.posedge, rst.async) {
    count = count + 1;  // syncブロック内では自動的にレジスタ更新
}

comb {
    result = a + b;     // combブロック内では組み合わせ論理
}
```

### 0.3.2 組み合わせ回路の明示的記述

`let`宣言または`comb`ブロックで組み合わせ論理を記述します。

```rust
// let宣言による組み合わせ回路
let sum = a + b;

// combブロックによる組み合わせ回路
comb {
    result = a & b | c;
}
```

### 0.3.3 順序回路の明示的記述

`sync`ブロックで順序回路を記述します。

```rust
// 可変信号の宣言（var推奨、let mutも可）
var counter: bit[8] = 0;

// syncブロックで順序回路を記述
sync(clk.posedge, rst.async) {
    if enable {
        counter = counter + 1;
    }
}
```

### 0.3.4 型安全性

暗黙の型変換を禁止し、すべての型変換は明示的に行います。

```rust
// エラー: 暗黙の型変換
let a: bit[16] = 8'hFF;  // コンパイルエラー

// 正しい: 明示的拡張
let a: bit[16] = (8'hFF).extend[16];
```

### 0.3.5 Multi Drive禁止

同一信号への複数箇所からの駆動（multi drive）はコンパイル時にエラーとして検出されます。

```rust
// エラー: 複数ドライバ
comb {
    if sel { result = a; }
}
comb {
    if !sel { result = b; }  // コンパイルエラー
}

// 正しい: 単一ドライバ
comb {
    result = if sel { a } else { b };
}
```

## 0.4 SystemVerilogとの比較

| 機能 | SystemVerilog | IRIS |
|------|---------------|------|
| 括弧 | `begin ... end` | `{ ... }` |
| 型宣言（組み合わせ） | `wire [7:0] data` | `let data: bit[8];` |
| 型宣言（順序） | `reg [7:0] data` | `var data: bit[8];`（推奨）<br>または `let mut data: bit[8];` |
| 分岐 | `case ... endcase` | `match { ... }` |
| 組み合わせ論理 | `assign` / `always_comb` | `let` 宣言 / `comb { }` |
| クロック | `always_ff @(posedge clk)` | `sync(clk.posedge) { }` |
| モジュール | `module ... endmodule` | `mod ... { }` |
| 代入演算子 | `=`（ブロッキング）<br>`<=`（ノンブロッキング） | `=`（統一） |
| 予約語数 | ~220 | ~54 |

## 0.5 Hello World

IRISでの最小限のカウンタモジュール：

```rust
/// 8ビットカウンタ
mod Counter(
    in  clk: clock,
    in  rst: reset,
    in  enable: bit,
    out count: bit[8],
) {
    // 可変信号（レジスタ）
    var counter: bit[8] = 0;

    // 順序論理
    sync(clk.posedge, rst.async) {
        if enable {
            counter = counter + 1;
        }
    }

    // 組み合わせ論理（出力接続）
    comb {
        count = counter;
    }
}
```

## 0.6 仕様書の構成

本仕様書は以下の章で構成されています：

1. **字句構造**: 文字セット、識別子、予約語、リテラル
2. **型システム**: プリミティブ型、複合型、ジェネリクス
3. **モジュール定義**: ポート、信号、インスタンス化
4. **組み合わせ論理**: let宣言、combブロック
5. **順序論理**: syncブロック、リセット処理
6. **FSM**: 状態機械の記述
7. **インターフェース**: ポートバンドル、ビュー
8. **演算子**: 算術、ビット、比較、論理演算
9. **メモリ**: RAM/ROM宣言
10. **検証機能**: テスト、アサーション
11. **パッケージシステム**: モジュール管理
12. **アトリビュート**: 合成指示
13. **エラーメッセージ**: エラーコード体系
14. **移行ガイド**: SystemVerilogからの移行
15. **文法定義**: EBNF形式
16. **サンプルコード集**: 実用例
17. **用語集**: 技術用語定義
