# RV32Iプロセッサ — IRIS言語のExample

## 概要

**RV32I**はRISC-Vの基本整数命令セットである。32ビット幅のレジスタを32本持ち、命令は40個しかない。
このExampleは、そのRV32Iを単サイクルのプロセッサとしてIRISで書き、
40命令すべてが仕様どおりに動くことをiris-simで確かめる。

これまでのExampleとは検証の性質が違う。
非同期FIFOは自分自身に対して検証していた。40語書いて40語読めることを確かめる、という形である。
プロセッサには外部の基準がある。
`ADDI x1, x0, 5`が`x1`に5を残すのは、RISC-Vの仕様がそう定めているからであって、
テストベンチが設計に同意したからではない。

IRISの次の機能を使っている。

- **`match`による多分岐**：命令デコードと演算選択
- **`mem`宣言**：レジスタファイル32本とデータメモリ
- **ビットスライスと連結**：命令フィールドの切り出しと即値の組み立て
- **`.sign_extend[N]()`／`.extend[N]()`**：符号拡張とゼロ拡張
- **`int[N]`型**：符号付き比較（SLT、BLT）
- **算術右シフト`>>>`**：SRA
- **ジェネリックパラメータ**：データメモリの語数
- **インスタンス階層**：コア、デコーダ、ALU、レジスタファイル

## 設計

### マイクロアーキテクチャ

単サイクルである。フェッチ、デコード、実行、メモリアクセス、書き戻しを1クロックで行う。

パイプラインにしていないのは意図的である。
主題は命令セットであってマイクロアーキテクチャではない。
パイプライン化するとハザードや転送の不具合が入り、
`SRAI`が正しく符号拡張するかという問題と混ざってしまう。

```
        ┌──────────┐
   PC ──┤ 命令ROM  ├── instr ──┬── Decoder ── 制御信号・即値
        └──────────┘           │
                               ├── RegFile ── rdata1, rdata2
                               │      ▲
                               │      └── 書き戻し
                               └── ALU ── 演算結果 ── データメモリ
```

命令メモリはコアの外にある。
`imem_addr`を出して`imem_rdata`を受け取る形にしてあるため、
テストプログラムごとに別のROMを繋ぎ替えられる。

### レジスタファイル

32本の32ビットレジスタを`mem`で持つ。読み出しポートは2本ある。
RV32Iのレジスタ間演算が`rs1`と`rs2`を同時に要るためである。

`x0`は仕様上つねに0である。これには2つの扱いが要る。

```rust
sync(clk.posedge, rst_n.async) {
    if we {
        if waddr != 5'd0 {      // x0への書き込みは捨てる
            regs[waddr] = wdata;
        }
    }
}

comb {
    // x0は記憶域を読まずに0を返す
    rdata1 = if raddr1 == 5'd0 { 32'd0 } else { regs[raddr1] };
}
```

書き込みを捨てるだけでは足りない。
読み出し側でも0を返さないと、リセット前の記憶域の値が見えてしまう。

### 即値の組み立て

RV32Iには5つの命令形式があり、即値のビット配置がそれぞれ違う。
とくにB形式とJ形式は、分岐先が2バイト境界であることを利用して
最下位ビットを省き、残りを飛び飛びに詰めてある。

| 形式 | 組み立て |
|------|---------|
| I | `instr[31:20]` |
| S | `instr[31:25]`, `instr[11:7]` |
| B | `instr[31]`, `instr[7]`, `instr[30:25]`, `instr[11:8]`, `0` |
| U | `instr[31:12]` を上位に置き下位12ビットは0 |
| J | `instr[31]`, `instr[19:12]`, `instr[20]`, `instr[30:21]`, `0` |

IRISでは連結してから符号拡張する。

```rust
imm_b = {instr[31], instr[7], instr[30:25], instr[11:8], 1'b0}.sign_extend[32]();
imm_j = {instr[31], instr[19:12], instr[20], instr[30:21], 1'b0}.sign_extend[32]();
```

仕様第9.7.2節は`{{20{instr[31]}}, instr[31:20]}`という反復を使う書き方を載せているが、
反復はiris-simが受け付けない。`.sign_extend[N]()`を使う。

### 符号の扱い

間違えても動いてしまう場所が2組ある。

| 組 | 違い |
|----|------|
| `SLT` と `SLTU` | 符号付き比較と符号なし比較 |
| `SRA` と `SRL` | 算術右シフトと論理右シフト |

IRISでは`int[32]`型の中間値を作って区別する。

```rust
var sa: int[32] = 0;
var sb: int[32] = 0;
comb {
    sa = a;
    sb = b;
    y = match op {
        4'd3 => if sa < sb { 32'd1 } else { 32'd0 },   // SLT  符号付き
        4'd4 => if a < b { 32'd1 } else { 32'd0 },     // SLTU 符号なし
        ...
    };
}
```

### データメモリ

ワード単位で持つ（`mem dmem: bit[32][DataWords]`）。
バイトとハーフワードのアクセスは、語の中の位置を`addr[1:0]`で選ぶ。
書き込みは語を読んで該当部分だけ差し替えてから書き戻す。

アラインメントは検査しない。`addr[1:0]`をそのまま語内位置として使う。

### 停止

`ECALL`と`EBREAK`はどちらも停止として扱う。
`halted`を1にし、テストベンチから観測できるようにする。
トラップは実装していない。RV32Iの範囲外である。

`FENCE`はnopとして退役する。守るべきメモリ順序がないためである。

## 検証方法

### 期待値の出どころ

期待値はRISC-Vの仕様から人が導く。**コアが出した値を期待値にしない。**
コアの出力から逆算すると、確かめたことにならない。

命令の符号化は`riscv64-unknown-elf-as`で組み立てている。
自分で符号化すると誤りが混ざるうえ、アセンブラのほうが権威がある。

### 進め方

コアが停止したら、レジスタ`x0`から`x31`までを1サイクルに1本ずつ読み、
期待値表と突き合わせる。

```
=== TestAlu ===
  instructions verified: 21
  registers checked:     32
  mismatches:            0
  RESULT: PASS
```

レジスタの中身は検証用ポート（`dbg_addr`／`dbg_data`）で見る。
`core.rf.regs[1]`のように階層越しに読むこともできるが、
ポートにしておくとテストベンチが何を見ているかが宣言に現れる。

### 取り違えを捕まえる値の選び方

もっともらしい間違いがもっともらしい答えを出す組み合わせは、
2つの挙動を区別できる値で試す。

| 命令 | それらしく見える間違い | 区別する値 |
|------|---------------------|-----------|
| `SRA` / `SRL` | 算術と論理の取り違え | `-16 >> 5` は `0xFFFFFFFF` か `0x07FFFFFF` |
| `SLT` / `SLTU` | 符号の取り違え | `-1 < 1` は真、`0xFFFFFFFF < 1` は偽 |
| `LB` / `LBU` | 符号拡張とゼロ拡張の取り違え | `0xEF` は `0xFFFFFFEF` か `0x000000EF` |
| `LH` / `LHU` | 同上 | `0xCDEF` は `0xFFFFCDEF` か `0x0000CDEF` |
| `BLT` / `BLTU` | 符号の取り違え | 負の値と小さい正の値を比べる |
| `JALR` | 最下位ビットを落とし忘れる | 飛び先を奇数にし、着地点のPCが偶数か見る |
| `AUIPC` | 次のPCに足す | `jal`の戻り番地と`auipc`の値が一致するか見る |
| `x0` | 書き込みが通る | `addi x0, x0, 7` のあと`x0`が0か見る |

`AUIPC`の検査は命令の配置に依存しない形にしてある。

```
    jal x27, next       # x27 = 次の命令の番地
next:
    auipc x28, 0        # x28 = この命令の番地
    sub  x29, x28, x27  # 0でなければどちらかが誤り
```

### 打ち切り

コアが停止しないと検証そのものが走らない。
何も報告しないまま成功扱いで終わってしまうため、400サイクルで打ち切る。

```
=== TestSys ===
  RESULT: FAIL - core did not halt within 400 cycles
```

これは机上の心配ではない。
`AUIPC`をわざと壊したところ、`JAL`の飛び先も変わってコアが暴走し、
打ち切りを入れる前は「成功」と表示されて終わっていた。

### わざと壊して確かめる

落ちないテストに価値はない。PASSを信じる前に、壊してFAILに変わることを確かめてある。

| 壊し方 | 結果 |
|--------|------|
| `SRA`を論理シフトにする | FAIL 2件 |
| `SLT`を符号なし比較にする | FAIL 1件 |
| `LB`をゼロ拡張にする | FAIL 2件 |
| `BLTU`を符号付き比較にする | FAIL 1件 |
| `JALR`の最下位ビット除去を外す | FAIL 3件 |
| `AUIPC`を次のPCに足す | 打ち切りでFAIL |
| `ECALL`で停止しない | 打ち切りでFAIL |

## 実行方法

### 前提条件

- Rust 1.70以降とcargoがインストールされていること

### シミュレーションの実行

```bash
cd example/riscv/sim
./run.sh
```

コンパイル型で実行する場合は次のとおりである。

```bash
./run_compiled.sh
```

### 期待される結果

```
=== Summary ===
  instructions verified: 40 / 40
  RESULT: PASS - all 40 RV32I instructions behave as the specification requires
```

内訳は次のとおり。

| テスト | 命令 | 数 |
|--------|------|---|
| `test_alu` | R形式10、I形式9、`LUI`、`EBREAK` | 21 |
| `test_mem` | ロード5、ストア3、分岐6、`JAL`／`JALR`、`AUIPC` | 17 |
| `test_sys` | `FENCE`、`ECALL` | 2 |

`EBREAK`は`test_alu`と`test_mem`の停止そのものが検証になっている。
停止しなければ打ち切りに掛かってFAILになる。

## SystemVerilogへの変換

このコアはSystemVerilogへ変換して、SystemVerilogのシミュレータでも動かせる。
変換した結果は`example/riscv/sv/`にある。

| ファイル | 内容 |
|---------|------|
| `regfile.sv`、`alu.sv`、`decoder.sv`、`riscv_core.sv` | iris2svで変換したコア |
| `rom_alu.sv`、`rom_mem.sv`、`rom_sys.sv` | iris2svで変換した命令ROM |
| `riscv_tb.sv` | SystemVerilogのテストベンチ（手書き） |
| `run.sh` | Verilatorでビルドして実行する |

### 実行

```bash
cd example/riscv/sv
./run.sh
```

IRISソースから変換をやり直す場合は`--regenerate`を付ける。

結果はIRIS版と同じである。

```
=== Summary ===
  instructions verified: 40 / 40
  RESULT: PASS - the converted core behaves as the specification requires
```

### 命令ROMは手書きしていない

テストベンチだけが手書きである。
iris2svは`test`モジュールを変換できるが、ここでは意図して使っていない。
変換したコアを、変換に使っていない経路で検証するためである。

命令ROMは`mod`なので変換できる。
`test`モジュールと同じファイルにあるため、切り出してから変換している。
40命令分の符号化を書き写すと写し間違いが入るので、IRIS側の1か所にとどめてある。

期待値の表も、IRIS版のテストを生成したのと同じ出所から作った。
IRIS版とSystemVerilog版で期待値がずれることがない。

### 変換のために直したもの

このコアを変換するには、iris2svに3件の不具合があった。
いずれも仕様が定め`iris-sim`が実行する構文であり、iris2svだけが違っていた。

| 不具合 | 内容 |
|--------|------|
| `match`式 | 仕様第5章が定めるのに変換できなかった。条件演算子の連鎖にする |
| `.sign_extend[N]()` | 幅引数を持つメソッド呼び出しの形を解釈できなかった |
| `=>`の後の`{` | 連結とブロックを区別できず、常にブロックとして解析していた |

`match`式は条件演算子の連鎖にした。
一時信号を作って`always_comb`の`case`にする案もあったが、
一時信号は収束が要り、単サイクルのコアでは置き場所を誤ると古い値を読む。
1行が長くなる読みにくさより、評価順序を変えない安全を採った。

### わざと壊して確かめる

変換が通っただけでは何も言えない。
**変換した`.sv`を直接壊して**、FAILに変わることを確かめてある。

| 壊し方 | 結果 |
|--------|------|
| 無改変（対照） | PASS |
| I形式の即値を符号拡張しない | FAIL |
| `LB`をゼロ拡張に壊す | FAIL |
| `SRA`を論理シフトに壊す | FAIL |
| 停止しないよう壊す | 打ち切りでFAIL |

### シミュレータの選択

Verilatorを使う。Icarus Verilogは`always_*`内のパート選択を扱えず、
このコアはそれだらけである。

## 実装時に当たったシミュレータの制限

このExampleを書いたときに4件の不具合が見つかった。
いずれも診断が出ず、値だけが静かに違うものだった。
**4件とも修正済みである。** 経緯を残しておく。

プロセッサは中間信号、階層アクセス、ビットスライスが密に並ぶ。
FIFOよりはるかに密であり、そのために表に出た。

### 直った4件

| 不具合 | 症状 | いまの挙動 |
|--------|------|-----------|
| モジュール直下の`let` | 非定数で初期化すると時刻0で1度だけ評価され、以後更新されない | 連続代入されるwireになる（仕様第4.3.2節） |
| インスタンス出力のスライス | `u.y[1:0]`が0を返す | 正しく取り出せる |
| インスタンス内`mem`の階層読み | `u.m[1]`が0を返す | 段数を問わず読める |
| 未知のメソッド | `.sext[32]()`が0を返す | `O1006`で報告される |

いちばん実害があったのは2番目である。
`alu.y[1:0]`が常に0のため、オフセット付きのロードとストアが
すべて基準アドレスを指していた。
読み出し18語目から24語目に34から40が現れ、FIFOのように未読データを上書きしていた。

どれもコンパイルは通り、lintも通る。
40命令が仕様どおりの値を出すことを確かめて初めて表に出た。

### いまも残っているもの

第1部で見つかった不具合はすべて直った。

階層越しの`mem`読み出しも段数を問わず動く。

```rust
comb { x = u.m[1]; }              // 1段
comb { x = core.rf.regs[1]; }     // 2段
```

このExampleは検証用ポート（`dbg_addr`／`dbg_data`）を残してある。
階層越しに読めるようになったので必須ではないが、
テストベンチが何を見ているかが宣言に現れるため、そのほうが読みやすい。

### このExampleの書き方について

上の4件が直る前は、回避策としてこう書いていた。

- 中間信号をすべて`var`にして`comb`で代入する
- インスタンス出力をいったん`var`へ写してからスライスする
- レジスタファイルに検証用の読み出しポート（`dbg_addr`／`dbg_data`）を設ける

どれももう必須ではない。
このExampleはそのままにしてある。
`var`＋`comb`は単サイクル設計として自然であり、
検証用ポートはテストベンチの意図が宣言に現れるためである。
ただしこのExampleはその書き方のままにしてある。
`var`＋`comb`は単サイクル設計として自然であり、
検証用ポートはテストベンチの意図を明示するのに役立つためである。

## 制限事項

- 単サイクルであり、パイプライン化していない
- 特権アーキテクチャ、CSR、割り込み、トラップは実装していない。
  `ECALL`と`EBREAK`は停止するだけである
- 圧縮命令（C拡張）と乗除算（M拡張）は範囲外である
- アラインメントを検査しない。
  非アラインのロード・ストアは`addr[1:0]`を語内位置として扱う
- 命令メモリはアドレスに対する`match`である。
  `mem`の初期化子がiris-simで使えないためであり、
  プログラムを差し替えるにはROMモジュールを書き換える
