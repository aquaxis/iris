# IRISのフォーマルベリフィケーション

## この資料が扱うもの

IRISで書いた設計と、`iris2sv`がそれを変換したSystemVerilogが、
同じ回路であることを証明する仕組みである。

```bash
tools/formal/run.sh
```

証明は3つの判定しか返さない。

| 判定 | 意味 |
|---|---|
| proven | すべての入力、到達しうるすべての状態で一致する |
| disproven | 一致しない。反例が出る |
| skipped | 試していない。理由が出る |

**エラーが無いことを成功と読まない。**
`sat`に`-prove-asserts`を付けなければ、証明が終わらなくても終了0になる。
`equiv_status`に`-assert`を付けなければ、未証明のセルが残っても終了0になる。
どちらも成功のように読める出力を出す。

## なぜベクタでは足りないか

`example/comparison/equiv/`のテストベンチは、すでに2つの回路を突き合わせている。

| テストベンチ | 与える刺激 | 検査数 |
|---|---|---|
| `alu_equiv.sv` | 16演算 × 境界値64組、続けて16演算 × 乱数2000組 | 33,024 |
| `ctr_equiv.sv` | 500サイクルのクロック動作と、リセットパルス | 501 |

ALUの入力空間は4 + 32 + 32ビットで2^68通りある。
33,024本はその10^-15にも満たない。

境界値の選び方は良い。
`0x8000_0000`と`0x7FFF_FFFF`が入っているのは、
SLTとSLTU、SRAとSRLが符号の境界でしか差を出さないためである。
それでも、良く選んだ標本は標本である。

**ベクタは差を見つけることしかできない。**
**差が無いことは言えない。**

## 何を証明しているのか

「等価」は1つの主張ではない。
道具を選ぶ前に語を固定する。

| 種別 | 主張 | 手段 |
|---|---|---|
| 組み合わせ | すべての入力の組に対し、すべての出力が一致する | miterの上のSAT |
| 順序、段数付き | 共通のリセット状態から`k`サイクル、出力が一致する | BMC |
| 順序、段数無し | 到達しうるすべての状態、すべての入力に対し、永久に一致する | 時相帰納法 |

**この仕組みが返す`proven`は3つ目である。**
段数の記載が無い`proven`は、段数が無いという意味である。

帰納が閉じない場合は`proven`にしない。
段数付きの結果を段数無しとして報告することが、この作業で起こりうる最悪の失敗である。

### この主張が黙っていること

5つは構成上除かれる。
いずれも見落としではなく、意図した限界である。

**XとZ。**
`prep`の後、yosysは2値で考える。
IRISの型体系にXは無いので基準側では何も失われないが、
実装側のX伝播の差はこの流れには見えない。
Verilatorの4値模擬実行が、そこの検査として残る。

**タイミング。**
両モデルともサイクル水準である。
毎サイクル出力が等しいことは、ネットリストがタイミングを満たすかについて何も言わない。

**またぎが正しいこと。**
`example/async_fifo`は2つのクロックをまたぐ。
`equiv_make`は両方のクロックを自由入力として扱うので、
どんな波形に対しても2つのモデルが同じに振る舞うことは証明できる。
言えないのは、同期段数がそこで起こる準安定に足りているかである。
それは設計の問題であって、変換が設計を保ったかとは別である。

**ポートの外側。**
内部信号は違ってよい。
違ってよいからこそ、証明が字面ではなく挙動についてのものになる。

**浮動小数点（`f32`／`f64`）。**
yosysは`prep`の後2値で考える。`miter`／`equiv`／`sat`はビットベクタを扱い、
IEEE 754の実数（SVの`real`／`shortreal`）はそこでビット分解できない。
だから基準側の生成器は浮動小数点の型を**明示的に拒否する**（黙って落とさない）。
インタプリタとコンパイル型は浮動小数点を評価するが、形式的等価性はこの流れの外にある。
これは未実装の穴ではなく、道具（yosys）の性質から来る意図した限界である。

## 2つの「下ろし方」は独立でなければならない

比べるには両側の形式モデルが要る。

**基準モデルを`iris2sv`が下ろしたIRから作ってはならない。**
下ろし方の不具合が両側に同じように現れ、miterは充足され、
証明は実行時間の長い同語反復になる。

**独立しているのは「下ろし方」である。**
`iris2sv`はRustへ移植され（段A4）、`iris-sim`の構文解析器を再利用するようになった。
よって基準側（`iris-formal`）と検査対象（`iris2sv`）は**フロントエンドを共有する**
（字句解析器・構文解析器・AST・`Project`）。共有しないのはSystemVerilogへの下ろし方で、
基準側はわざと素朴に（`if`/`else`、幅付きリテラル、キャスト無し）、`iris2sv`は慣用的に
（入れ子の三項、`N'(...)`キャスト、インライン化）出す。**別々のコード経路である。**

| | 構文解析 | SystemVerilogへの下ろし方 |
|---|---|---|
| `iris-formal`（基準） | `iris-sim`の`iris.pest`（共有） | 素朴・構造的（`sim/iris-sim/src/formal/`） |
| `iris2sv`（検査対象） | `iris-sim`の`iris.pest`（共有） | 慣用的（`tools/iris2sv-rs`） |

だから**下ろし方の食い違い**は、この流れが表に出す（本来の目的）。
一方、共有するフロントエンドの不具合はここでは捕まらない（両側が同じように壊れる）。
それはインタプリタ、conformanceの往復検査、そしてVerilator自身のSystemVerilog
フロントエンド（`iris2sv`の出力を独立に読む）が受け持つ。

**注記**：移植前の`iris2sv`はTypeScriptの独立な構文解析器を持ち、フロントエンドも
独立だった。Rust化（利用者の指示「irisはRustで実装する」）でフロントエンドは共有に
なり、独立性は「下ろし方」の層に移った。往復・Verilatorの独立性は残る。

## 道具の形

| 部品 | 形態 | 置き場所 |
|---|---|---|
| 基準モデルの出力部 | 既存への追加 | `sim/iris-sim`の3本目のバイナリ`iris-formal` |
| 証明の駆動部 | 新規ツール | `tools/formal/` |

基準モデルはRustの構文解析器とASTの上に置く。
`iris-sim`のASTと`Project`をそのまま使えるからで、外に出せばそれらを再実装することになる。
（`iris2sv`も同じ構文解析器を使うので、独立しているのは構文解析ではなく下ろし方である。）

駆動部は基準側と実装側の両方から等距離に立つ必要がある。
どちらかのツールの中に置くと、その条件を守っているかが読んで分からなくなる。

## 経路

```
design.iris
   ├── iris-formal （Rust、pest）  → reference.sv  構造的、1行に1構文
   └── iris2sv     （Rust、pest）  → impl.sv       慣用的（下ろし方は別経路）

         両方 → yosys: read_verilog -sv
                       hierarchy -check -top
                       proc; opt; memory_map; opt
                       flatten; opt        （それぞれ別に、design -stash で）
                     ├── 組み合わせ: miter -equiv -flatten -make_assert
                     │               sat -verify -prove-asserts
                     └── 順序:       prep; async2sync
                                     equiv_make; equiv_simple; equiv_induct
                                     equiv_status -assert
```

基準モデルは意図的に鈍い。

- レジスタ1つに`always_ff`1つ、リセットの枝を明示
- `always_comb`は素の`if`／`else`と`case`、三項演算子の連鎖にしない
- リテラルはすべて幅を持つ
- `alu.y`のようなインスタンス出力の読みは線とポート接続になる
- 宣言の初期値をそのまま再現する
- IRISの幅の意味論を写す。`bit[5]`どうしの加算は`5'(...)`で切り詰める

**両側を`write_verilog`で書き出して読み直してはならない。**
`write_verilog`はyosysの内部名`$auto$...`を綴れないので、`_000_`、`_001_`と振り直す。
無関係な2本の線が同じ名前を持ち、名前で対応付ける`equiv_make`がそれを繋ぐ。
RV32Iのコアでは`_016_`が片方で`~halt_reg`、他方で`~dec.is_system`だった。
偽の対応は差を証明に変えることはできないが、検査の範囲を黙って狭める。

`iris2sv`はこの逆で、入れ子の三項演算子と`32'(...)`のキャストと畳み込んだ論理を出す。
yosysのフロントエンドの不具合が本物の差を隠すには、
その2つを同じ向きに壊さねばならない。

## 状態、リセット、初期値

サイクル精度の等価性証明が、誰にも気づかれずに間違っているのはたいていここである。

### リセット

`iris2sv`は非同期リセットを感度リストに出し、yosysはこれを`$adff`とする。
`equiv_induct`は同期的な状態について考えるので、対応付けの前に`async2sync`をかける。

**`async2sync`は証明の対象を変える。**
「`rst`が高い間はいつでもクリアされる」を
「`rst`が高いまま次のクロックエッジが来たらクリアされる」に置き換える。

同じIRIS原本から作った2つは、両方が同じ変換を通るので、これは受け入れられる。
ここに書くのは、エッジ間でリセットを叩くベクタのテストベンチと比べた読み手が、
そうと知らずに食い違いと結論しないためである。

### 初期値

仕様6.3.1はこう定めている。

```
リセット値は`var`宣言時の初期値から決定されます。
```

両側ともこの規則で動く。
初期値の無い信号にはリセットの代入を作らない。戻す先が無いためである。
リセットすべきものが1つも無い場合は、感度リストからリセットを外す。
そのエッジで変わると言いながら、どう変わるかを言わない記述にしないためである。

### メモリ

`mem`は`memory_map`で明示的に展開する。
どちらがたまたま推論を起こしたかに依存させず、両側を同じように扱うためである。

`sync`の中の代入は`<=`で出す。
IRISは代入演算子を1つに統一し、`sync`の中で順序回路の意味を与えるが、
SystemVerilogはそうではない。
`dmem[addr] = word`と書くとyosysがメモリを推論できず、
1024語の配列が32ビットのデコーダを伴う32,768個のレジスタになる。

## 証明器そのものを検証する

SUCCESSと報告する流れと、無条件にSUCCESSと報告する流れは、出力からは区別できない。

**すべての証明に、落ちなければならない変異を1つ添える。**

| 設計 | 変異 |
|---|---|
| `alu` | SLTの枝の符号付き比較を符号無しにする |
| `alu` | SRLとSRAを入れ替える |
| `counter` | 増分を2にする |
| `decoder` | I形式の即値の符号拡張を落とす |
| `regfile` | `x0`への書き込み禁止条件を外す |

流れが**通してしまう**変異は、流れの不具合である。
設計の不具合と同じ重さで扱う。

## 判定が出ないとき

証明が終わらないのは証明ではなく、
待ち続ける駆動部は何も報告しないのと同じである。

時間予算を置き、超過は`skipped`として予算とともに報告する。

```bash
FORMAL_TIMEOUT=3000 tools/formal/run.sh riscv_core
```

**`skipped`は合格ではない。**
この流れが何も言えなかった設計であり、失敗と同じ大きさで報告する。
緑の行が、無い行の代わりになってはならない。

## いま言えていること

2026-08-12に測った。

| 設計 | 読める | IRISとの等価性 | 往復の等価性 |
|---|---|---|---|
| `alu` | 可 | proven、段数無し | proven |
| `decoder` | 可 | proven、段数無し | proven |
| `counter` | 可 | proven、段数無し | proven |
| `regfile` | 可 | proven、段数無し | proven |
| `async_fifo` | 可 | proven、段数無し、178セル | proven |
| `riscv_core` | 可 | proven、段数無し | proven |

`riscv_core`は1024語×32ビットのデータメモリを持ち、
`memory_map`の後は両側で65,536個のフロップになる。
これが最後まで残ったが、**時間だけの問題だった。**

| 深さ | 結果 | 時間 |
|---|---|---|
| 4語 | proven | 9秒 |
| 16語 | proven | 14秒 |
| 64語 | proven | 46秒 |
| 256語 | proven | 372秒 |
| 1024語（実物） | proven | 約80分。往復も約73分 |

既定の予算240秒では届かない。

```bash
FORMAL_TIMEOUT=9000 tools/formal/run.sh riscv_core
```

`equiv_make`はメモリを受け付けない。

```
ERROR: Gold module contains memories or processes. Run 'memory' or 'proc' respectively.
```

そのため`memory_map`で展開したまま証明している。
**メモリを比較から外す抽象は使っていないので、**
**配列が等しいという仮定は残る信頼の一覧に入っていない。**

**基準モデルは独立に走らせても正しい。**
`example/riscv/sv/riscv_tb.sv`に`iris-formal`の出力を繋いでVerilatorで走らせ、
RV32I 40命令が不一致0で通る。
証明が落ちたときに、どちらのモデルが間違っているかを決める材料になる。

## 残る信頼

流れが証明しないもの、したがって信頼しているもの。

- **yosysのSystemVerilogフロントエンド。** 両側が通る
- **`async2sync`変換。** 両側に等しくかける
- **IRISの言語定義と共有フロントエンド。** 基準側と検査対象は同じ構文解析器・ASTを使うので、そこの不具合はこの流れに現れない（両側が同じに壊れる）。仕様どおりに読めているかは別途、往復検査とVerilatorが受け持つ
- **基準モデルの出力部そのもの。** 読めるように小さく鈍く作るが、コードであり、証明されてはいない

**この一覧は成果物である。**
仮定を書かない形式的結果は、稼いだ以上の信用を集める。

## この仕組みが見つけた不具合

形式検証を建てる過程で、既存のツールの不具合が9件出た。
詳細は`.aiprj/AI_PRJ_TASKS.md`の追跡簿にある。

| ID | 症状 | 部品 |
|---|---|---|
| D-1 | `always_ff`の感度リストにリセットがあり、本体にリセットの枝が無い | `iris2sv` |
| D-2 | インスタンス出力を接続せず階層参照で読む | `iris2sv` |
| D-3 | `truncate`を受け付けない | `iris2sv` |
| D-4 | 2段の階層越しにポートを読むと0が返る | `iris-sim` |
| D-5 | 評価失敗が終了ステータスに出ない | `iris-sim` |
| D-6 | 幅変換メソッドを`.sign_extend(32)`と出す | `sv2iris` |
| D-7 | 文法どおりの`where`句を解析できない | `iris2sv` |
| D-8 | 型の幅の式を`/* expr */`と出し、成功と報告する | `iris2sv` |
| D-9 | 幅キャストの式を`/* width */`と出し、成功と報告する | `iris2sv` |

D-1は、リセットの立ち上がりでカウンタが増える回路を出していた。
Verilatorは通し、871件のテストも通っていた。
yosysが受け付けないことで表に出た。

D-2は21箇所の階層参照を駆動されない線に変え、
それに対する証明は、ALUの入力が浮いたコアについての証明になっていた。
**黙って間違ったモデルを作るほうが、拒否されるより悪い。**

D-8とD-9は、`async_fifo`の往復が反証されたことで出た。
`iris2sv`が`/* expr */`と`/* width */`というコメントを幅として出し、
そのうえで変換に成功したと報告していた。

この流れは自分の欠陥も5件出している。
宣言の初期値を出していなかったこと、
IRISの幅の意味論を写していなかったこと、
中間のVerilog書き出しが偽の対応を作っていたことなどである。
記録は`.aiprj/AI_PRJ_TASKS.md`にある。

## 前提条件

- `yosys` 0.52以降（`miter`、`sat`、`equiv_*`、`async2sync`が要る）
- `node`
- `iris2sv`のビルド（`make -C tools iris2sv`）
- `iris-formal`のビルド（`cargo build --release --manifest-path sim/iris-sim/Cargo.toml`）

SymbiYosysは使っていない。
この機械に入っていないため、yosysを直に叩いて書いてある。
